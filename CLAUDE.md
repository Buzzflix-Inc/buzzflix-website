# Buzzflix website

Hand-built static site for Buzzflix (student film production company, Windsor ON). No build step and no dependencies: the repository root is what Cloudflare Workers serves (`wrangler.jsonc`).

## Files

- Pages: `index.html`, `mentors.html`, `movies.html`, `apply.html`, `yearbook.html`, `privacy.html`, `404.html`. Served at `/`, `/mentors`, `/movies`, `/apply`, `/yearbook`, `/privacy`; internal links use the `.html` names and Cloudflare redirects them.
- Homepage: never edit `index.html` directly. Edit `home-current.html` (normal) or `home-applications.html` (application season, Jan to Mar/Apr), then run `node scripts/switch-home.mjs current|applications` to copy one to `index.html`. Keep shared changes in both sources.
- Header, footer and `<head>` are repeated in every page. A change to them must be made in all seven page files (and both homepage sources).
- CSS: `assets/css/site.css` holds everything, in order: fonts, tokens, base, components, pages. Each part has its own `@media(max-width:800px)` block. `assets/css/application.css` loads only on the application homepage and `apply.html`.
- JS: `assets/js/main.js` (mobile menu, carousel dragging and arrow keys, the 404 slate). When the slate's take reaches 04 (and every fourth take after), it loads `bee-game.js`, the Buzz Run minigame. Its shared top 10 is stored by `worker/leaderboard.js` (run through `worker/index.js`, which `wrangler.jsonc` sends `/api/*` and `/staff*` to) in the D1 database `buzzflix-buzz-run` (`worker/schema.sql`). A score needs a run id from `/api/buzz-run/runs` that is old enough for it. Remove a bad entry in the Cloudflare dashboard (D1 → buzzflix-buzz-run → scores). Test with `node --test scripts/test-leaderboard.mjs`; `serve.mjs` runs the same API with scores in memory. The application form is `application-form.js` and `application-config.js`; it posts to `/api/apply` (`worker/apply.js`), which stores applications and drafts in the D1 database `buzzflix-applications` and PDFs in the R2 bucket `buzzflix-application-documents`, and emails through Resend (`worker/mail.js`).
- `apply.html` is the 2027 application page. Applicants pick three positions by department (`assets/js/apply-picker.js`), which fills the form's three read-only role fields; the form can't be submitted without three picks. The form is a preview-only copy: `data-preview` keeps it from sending, and shows **Email me my answers**, which saves a draft through `/api/apply` and emails a `/apply#draft=<id>` link that refills the form (see `STAFF-AREA.md`). The picker's eight groups are a short selection from the intake portal's `src/js/data/departments.js`.
- Staff area: `/login` (not linked anywhere, `noindex`) emails a sign-in code to any @buzzflix.ca address; `/staff/` (applications list), `/staff/application?id=`, `/staff/new` (add one by hand) and `/staff/team` are guarded by `worker/staff.js`, which also sets the hiring steps (`allowedStatuses`: assigning a New application moves it to In review, members recommend Approve/Decline after an interview, admins make the final Hired/Not hired call). Open staff pages poll `/api/staff/changes` every 10 seconds (`watchChanges` in `staff-common.js`) so several people can work at once and see who has which application open. Scorecard questions and applicant email templates are in `worker/hiring.js`; `APPLICANT_EMAILS` (wrangler.jsonc) turns sending on. Pages are `login.html` and `staff/*.html` (their own header, `assets/css/staff.css`, `assets/js/staff-*.js`). Setup, settings and the Apps Script cutover are in `STAFF-AREA.md`. Test with `node --test scripts/test-staff.mjs`; `DEMO=1 node scripts/serve.mjs` adds made-up applications and prints sign-in codes in the terminal.
- `consent_version` and the department list must match in `application-form.js`/`apply.html` and `worker/apply.js`. `apps-script/Code.gs` is the old Google Apps Script backend, kept until saved drafts are moved across (`STAFF-AREA.md`).
- Docs: `APPLICATIONS.md`, `STAFF-AREA.md`, `APPS-SCRIPT-SETUP.md`, `CLOUDFLARE-CUTOVER.md`.

## Rules

- Match the existing look: tokens in `site.css` (`--yellow`, `--orange`, `--ink`, `--muted`), Space Grotesk 500 headings, Roboto 400 body, 800px breakpoint. Check every change at phone and desktop widths.
- Contrast: orange text on yellow uses `--orange-text` at 24px or larger (passes WCAG AA). Buttons are white 16px text on the brand `--orange` (3.4:1), which Lighthouse flags; this is a deliberate brand choice, so don't darken the orange or change the button text to fix it.
- Images live in `assets/images/<slug>-<7 hex>.<ext>`, mostly WebP. `_headers` caches images and fonts for a year, so a new or changed file needs a new name. Every `<img>` carries the file's real `width`/`height`, `loading="lazy"` unless it is above the fold, and the page's top photo gets `fetchpriority="high"`. Focal points go in `style="object-position:…"` (omit it for the 50% 50% default).
- Fonts in `fonts.css` section: only the faces in use (Roboto 400, 400 italic, 700; Space Grotesk 400, 500), Latin and Latin Extended. Every font a page uses is preloaded in its `<head>`, so none waits for the CSS (Lighthouse's "network dependency tree"): Roboto 400 and Space Grotesk 500 Latin at normal priority on all pages; Space Grotesk 400 (application banner, movies.html and mentors.html only) and Roboto italic (mentors.html only) with `fetchpriority="low"` so they don't compete with the hero photo. A page that starts using another font face needs its own preload.
- Link text must describe the destination (Lighthouse SEO flags "More Info", "here", "learn more"). Keep a short visible label by adding hidden context, e.g. `More Info<span class="visually-hidden"> on YouTube</span>`.
- `_headers` sets a Content-Security-Policy. Any new outside service (scripts, embeds, form endpoints, fonts) must be added there or browsers will block it. It also needs a line in `privacy.html`, which lists everything the site collects or loads (application form, saved drafts, Buzz Run initials, Cloudflare, browser storage, YouTube, OpenStreetMap); change its "Last updated" date with it.
- New pages go in `sitemap.xml`.
- Structured data: the FAQs on `apply.html`, `movies.html` and `mentors.html` are copied into FAQPage JSON-LD in each `<head>`. After editing an FAQ, run `node scripts/faq-schema.mjs`. The Movie entries in `movies.html` are written by hand; update them with the film cards. The homepage Organization block uses the wordmark as its logo.
- Share images: each page's `og:image` is its own 1200×630 JPG (`share-<page>-<hash>.jpg`), cropped from a page photo with `magick in.webp -resize 1200x630^ -gravity center -extent 1200x630 -strip -quality 82 out.jpg`. Keep `og:image:alt` matched to the picture.
- The footer's last row (copyright, privacy link, bee cursor switch) is `.footer-legal`; update the copyright year each January.
- Files that must not be public go in `.assetsignore` (Markdown, scripts, `apps-script`, homepage sources are already listed).

## Preview

`node scripts/serve.mjs` (or the `buzzflix` config in `.claude/launch.json`) serves the site like Cloudflare: pretty URLs, `_redirects`, `_headers`, `.assetsignore` and the 404 page. ES modules don't run from `file://`.
